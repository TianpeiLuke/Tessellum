to the existing `snippet_hermes_agent_*` implementation layer. **1 note per page (10 notes).**

  `procedure` note each. None mixes a standalone concept block exceeding 500w (the conceptual
  asides — "Golden Rule: self-contained prompts", "the `[SILENT]` trick", "the Context Problem" —
  are 1–3 sentence callouts embedded in the procedure, NOT separable concept notes).

  content: the full cron reference (SP06a `cron`), full delegation reference (SP06a `delegation`),
  full webhook platform reference (SP12b `webhooks`), Telegram/Discord/Slack setup (SP11a-b),
  Teams + Teams-meetings setup (SP11b), `hermes send` lives in this SP (no dedicated feature page).
- **Collision (augment): `term_cron` (active), `term_cron_expression` (active), `term_subagent`
  (active), `term_multi_agent_systems` (active), `term_autonomous_coding_agents` (active),
  `term_agent_orchestration` (active) are existing substantive terms** — LINK, do NOT recreate.
- **Collision: the messaging-gateway / delegate-task / persistent-goal concepts are owned by OTHER
  sub-plans** (`term_messaging_gateway`→SP11, `term_delegate_task`→SP06a, `term_persistent_goal`→SP06a)
  and do NOT yet exist in the DB → forward-ref `[own]` `(+fin)`, EXCLUDED from the ≥8 term floor.
- `operate-teams-meeting-pipeline.md` is an operator *runbook* (CLI flows + go-live checklist +
  worksheets) — still a single `procedure` BB; the worksheet tables are reference material kept in
