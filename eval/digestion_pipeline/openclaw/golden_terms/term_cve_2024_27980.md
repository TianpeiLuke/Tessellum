# CVE-2024-27980 — Node.js Windows .cmd/.bat Command Injection (BatBadBut)

## Definition

CVE-2024-27980 is a HIGH-severity (CVSS 3.0 base score 8.1, vector `AV:N/AC:H/PR:N/UI:N/S:U/C:H/I:H/A:H`, CWE-77) command-injection vulnerability in Node.js's `child_process.spawn` / `child_process.spawnSync` on Windows. When a Node.js program spawned a `.bat` or `.cmd` file (for example `npm.cmd`, `pnpm.cmd`, `yarn.cmd`) with user-supplied arguments and `shell: false`, an attacker could embed `cmd.exe` metacharacters in those arguments to inject and execute arbitrary commands — even though `shell: false` is documented as the safe mode that bypasses any shell.

The root cause is the BatBadBut class of bugs, disclosed in April 2024 by Flatt Security researcher RyotaK. Windows `CreateProcess` cannot execute batch files directly: it implicitly re-routes `.cmd`/`.bat` through `cmd.exe /c`. But `cmd.exe` has its own parser with a different escape character (`^` rather than `\`) and treats `&`, `|`, `<`, `>`, `^`, `%`, and embedded newlines (`\r`, `\n`) as control characters. Language runtimes — Node.js, Rust (CVE-2024-24576), PHP, Haskell, and yt-dlp — applied generic POSIX-style quoting that survived `CreateProcess` but was re-interpreted by `cmd.exe`, breaking the escape and re-exposing every metacharacter.

## Context

The vulnerability was patched on April 9-10, 2024 in Node.js v18.20.2, v20.12.2, and v21.7.3 (reported by ryotak, fixed by Ben Noordhuis). The patch is *breaking*: Node now refuses to spawn `.cmd`/`.bat` files directly when `shell` is not set and returns `EINVAL`. Callers that legitimately need batch-file execution must either (a) pass `{ shell: true }` after sanitizing arguments themselves, (b) resolve the underlying interpreter (e.g., `node.exe npm-cli.js` instead of `npm.cmd`), or (c) wrap the invocation in an explicit `cmd.exe /d /s /c` argv with safe-character validation. A `--security-revert=CVE-2024-27980` flag exists but is strongly discouraged.

Any Windows Node app that shelled out to package managers, build tools, or other `.cmd`-wrapped binaries with user-controlled args was vulnerable — a broad class that includes electron apps, CI runners, IDE extensions, and agent frameworks. OpenClaw's process subsystem at `src/process/exec.ts` is one example: it ships a defense-in-depth shim (`WINDOWS_UNSAFE_CMD_CHARS_RE`, `isWindowsBatchCommand`, `escapeForCmdExe`, `resolveTrustedWindowsCmdExe`, `resolveNpmArgvForWindows`) that survives both the pre-patch attack surface and the post-patch `EINVAL` behavior. For `npm.cmd` / `npx.cmd` invocations specifically, OpenClaw rewrites the argv to spawn `node.exe` with the resolved `npm-cli.js` script, avoiding the patched-Node EINVAL while preserving the security property.

## Key Characteristics

- **Trigger predicate**: command path ends in `.cmd` or `.bat` (case-insensitive); detected via `path.extname()` on the resolved command in OpenClaw's `isWindowsBatchCommand`.
- **Unsafe character class**: `/[&|<>^%\r\n]/` — the six `cmd.exe` metacharacter families that escape parsers cannot neutralize via quoting alone. OpenClaw's `escapeForCmdExe` rejects any argument matching this class with a thrown error rather than attempting to escape it.
- **cmd.exe argument escaping**: when an argument contains a space or `"`, OpenClaw wraps it in double quotes and doubles every inner `"` to `""` (`cmd.exe` requires `""` rather than `\"` for embedded quotes inside a quoted token).
- **Trusted `cmd.exe` resolution**: OpenClaw resolves `cmd.exe` via `path.win32.join(SystemRoot, 'System32', 'cmd.exe')` rather than relying on PATH lookup — a defense-in-depth measure against PATH hijack that compounds with the BatBadBut mitigation.
- **npm.cmd argv rewrite**: `resolveNpmArgvForWindows` detects `npm` / `npx` invocations and rewrites them to `[process.execPath, npm-cli.js, ...rest]`, bypassing the `.cmd` shim entirely (and therefore the Node 18.20.2+ EINVAL). Falls back to `<name>.cmd` when `npm-cli.js` is missing (Bun runs), still routed through the `cmd.exe` wrapper.
- **Breaking change**: the Node fix does not silently sanitize — it errors with `EINVAL` so callers cannot keep the vulnerable code path. Library authors must update their spawn call sites.
- **Severity context**: the parent BatBadBut family includes Rust's CVE-2024-24576 (CVSS 10.0), which has higher exploit-likelihood scoring than the Node entry; Java explicitly chose "won't fix" and Go/Python/Ruby/Erlang shipped documentation-only updates.
